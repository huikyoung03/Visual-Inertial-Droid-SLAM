# Installation and deployment guide

This guide recreates the environment used by the selected **alpha-750 15DoF
model**. It covers two intentionally separate environments:

1. `droid_env`: CUDA/PyTorch inference, training, preintegration and PLY export.
2. `.venv-phone`: the lightweight FastAPI/WebSocket server used to capture a
   phone camera stream and IMU samples. It invokes `droid_env` only when a
   capture has finished.

The separation prevents the web server's Python packages from changing the
CUDA runtime used by DROID-SLAM.

## 1. Tested software and hardware

| Component | Tested value |
| --- | --- |
| OS | Ubuntu 22.04 under WSL2 (native Linux is also expected to work) |
| Python | 3.8.20 |
| PyTorch | 2.4.1 + CUDA 11.8 (`cu118`) |
| CUDA compiler | 11.8.89 (`nvcc`) |
| GPU | NVIDIA GeForce RTX 4060 |
| NVIDIA driver | 595.95 |
| GCC/G++ | 11.4 |

An NVIDIA GPU is required. The host driver must support CUDA 11.8 (a current
production NVIDIA driver is recommended). A separate system-wide CUDA toolkit
is **not** required: the installer places `nvcc 11.8` in the Conda environment.
The driver itself cannot be installed by Conda.

## 2. System prerequisites

On Ubuntu/WSL2, first install the native build and OpenCV runtime libraries.

```bash
sudo apt update
sudo apt install -y build-essential gcc g++ cmake ninja-build git \
  libgl1 libglib2.0-0 libgomp1
nvidia-smi
```

Install Miniconda or Anaconda if `conda --version` is unavailable. In WSL2,
install an NVIDIA WSL-compatible Windows driver; do not install a second Linux
kernel driver inside WSL.

## 3. Clone, model assets, and CUDA environment

```bash
git clone --recursive <REPOSITORY_URL> DROID-SLAM
cd DROID-SLAM
```

Two checkpoint files are deliberately not ordinary Git files:

- `droid.pth`: obtain from the upstream DROID-SLAM release and place it at
  `DROID-SLAM/droid.pth`.
- `learned_cross_modal_alpha_localmatched_mh03_mh04_1k_000750.pth`: download
  the selected model from this repository's GitHub Release and place it at
  `DROID-SLAM/checkpoints/`.

Verify the selected model before use:

```bash
sha256sum checkpoints/learned_cross_modal_alpha_localmatched_mh03_mh04_1k_000750.pth
# expected: 63bdbb5965c683962ad382a9e7477a04b130ce58ec2e0752637babf8669eacfa
```

Create the CUDA environment and build the three custom extensions
(`lietorch`, `torch-scatter`, `droid_backends`):

```bash
bash scripts/install_droid_env.sh
conda activate droid_env
python scripts/verify_droid_env.py
```

`MAX_JOBS=2 bash scripts/install_droid_env.sh` is useful on memory-limited
machines. The build must use the environment's CUDA 11.8 compiler, not an
arbitrary system `nvcc`; the script exports `CUDA_HOME=$CONDA_PREFIX` before
building.

For optional desktop OpenGL visualization, install:

```bash
python -m pip install -r requirements-visualizer.txt
```

The documented final commands use `--disable_vis`, so this optional package is
not required for evaluation or phone deployment.

## 4. Run a prepared image sequence

Visual-only DROID needs an image directory and one-line camera calibration:

```bash
conda activate droid_env
python demo.py \
  --imagedir /path/to/images \
  --calib /path/to/calib.txt \
  --weights droid.pth \
  --stride 2 --buffer 512 --disable_vis \
  --reconstruction_path /path/to/original_reconstruction.pth
```

The learned 15DoF model additionally needs synchronized camera timestamps and
an IMU prior generated by `tools/imu_preintegrate.py`. For a reproducible
EuRoC V1_03 comparison, use the fixed final script:

```bash
cp configs/final_alpha750.env.example /tmp/final_alpha750.env
# Set every absolute path in /tmp/final_alpha750.env.
source /tmp/final_alpha750.env
EVAL_PREFLIGHT_ONLY=1 bash tools/run_final_alpha750_evaluation.sh
bash tools/run_final_alpha750_evaluation.sh
```

The final evaluation uses camera stride 2, `visual local ×3 → full 15DoF local
×2 → visual global ×7 → full 15DoF global ×12`, and a maximum IMU factor span
of 0.5 s. The full-trajectory dense Sim(3) report is written to
`$OUT_DIR/summary_full.md`.

## 5. Phone capture deployment

The deployable server is included in `phone_server/`. It uses native Android
sensor timestamps, writes a session directory, creates `imu_prior.csv`, runs
the alpha-750 15DoF model, exports a filtered metric PLY, and exposes a mobile
viewer.

```bash
bash scripts/install_phone_server.sh
bash phone_server/start_alpha750_server.sh
```

Open `http://<HOST_LAN_IP>:8000/` on the phone. The phone and host must be on
the same Wi-Fi network or hotspot. After capture stops, open the session's
viewer URL reported by the server.

The packaged profile targets the calibrated Galaxy S20 rear-wide 640×480
camera. It runs image input at 10 Hz with tracking stride 1 and intentionally
sets `imu_full_max_dt_sec=0` and `vi_init_max_dt_sec=0`: no IMU interval is
discarded solely because it exceeds 0.5 s. This is a deployment choice; it is
different from the fixed EuRoC benchmark protocol above.

Before using another phone, calibrate its intrinsics, camera–IMU rotation,
translation, timestamp offset, IMU bias, noise density, and random walk.
Never reuse the Galaxy S20 profile for a different camera/lens/sensor layout.

## 6. Common failures

| Symptom | Check |
| --- | --- |
| `CUDA is unavailable` | Run `nvidia-smi`; reinstall the cu118 PyTorch wheels; do not use a CPU wheel. |
| `nvcc`/extension build failure | Activate `droid_env`, confirm `nvcc --version` reports 11.8, then rerun the installer. |
| `No module named droid_backends` | The editable build did not finish; rerun step 5 of `scripts/install_droid_env.sh`. |
| Phone server cannot find DROID Python | Set `DROID_PYTHON=/absolute/path/to/env/bin/python` before starting it. |
| Phone cannot connect | Use the host LAN IP, not `localhost`; place both devices on the same LAN. |
| Profile blocks 15DoF | Do not bypass calibration on a new device. Add a correctly measured device profile. |

## 7. What is and is not reproduced

The selected alpha-750 checkpoint, exact SHA-256, final evaluation command,
and model structure are versioned. New training runs can differ because GPU
operations and sampling are stochastic. The EuRoC numbers document dense
Sim(3) trajectory shape error; they do not alone establish metric-scale error
because Sim(3) fits an oracle global scale.
